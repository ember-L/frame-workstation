# 项目结构

## 项目定位

Frame Workstation 是面向个人创作者的 macOS 桌面视频工具。首个目标平台为 Apple Silicon；使用 Electron 承载界面和系统能力，FFmpeg 负责媒体处理，后续接入 AI 字幕、配音与 Remotion 模板视频。

## 当前工作区

以下是截至 2026-11-14 的实际结构；它是早期原型，不能等同于已经验收的可发布应用。

```text
frame workstation/
├── package.json           # Electron、FFmpeg 依赖和运行、测试、打包命令
├── package-lock.json      # 当前依赖锁文件
├── README.md              # 项目入口和基本命令
├── src/
│   ├── main.js            # Electron 主进程、文件对话框、FFmpeg 导出
│   ├── preload.js         # 渲染进程可调用的有限接口
│   ├── export.js          # 导出参数校验与 FFmpeg 参数构造
│   ├── paths.js           # 源文件与输出路径保护
│   ├── subtitles.js       # SRT 解析、校验与生成
│   ├── distribution.js    # 打包前检查 FFmpeg 配置
│   ├── index.html         # 目前的编辑页面结构
│   ├── renderer.js        # 编辑页面交互
│   └── style.css          # 当前原型样式
├── test/
│   ├── export.test.js     # 导出参数的基础测试
│   ├── paths.test.js      # 源文件路径保护测试
│   ├── subtitles.test.js  # SRT 读写与校验测试
│   └── distribution.test.js # 打包配置检查测试
└── docs/
    ├── 项目结构.md
    ├── 功能文档.md
    └── 项目规划.md
```

`node_modules/` 为本地安装的依赖，不作为业务源码；`dist/` 为打包输出。依赖安装、应用启动和安装包打包是否成功，必须以实际执行结果为准。

## 职责与数据流

1. **渲染进程**负责预览、编辑控件、展示状态；不直接取得 Node.js 或系统文件权限。
2. **预加载层**通过受限接口转发用户操作。主进程仍需验证传入的参数、文件路径与任务状态。
3. **主进程**负责系统文件对话框、本地媒体访问、启动和管理子进程、报告错误。导出应写入临时文件，成功后再替换目标，不能覆盖源视频。
4. **FFmpeg**接收参数数组执行裁剪、变速、编码和封装；不通过拼接 shell 命令传递用户输入。
5. **后续 AI 和 Remotion 模块**应各自维护清晰的输入、输出和错误边界。模型、密钥与用户素材不放进代码仓库。

## 后续扩展方向（规划，尚未创建）

随着功能实际落地，再按需要拆分媒体任务、字幕与语音、AI 服务配置、模板与渲染、任务状态和设置等模块。暂不预建空目录或把具体文件树视为既定实现；具体边界随验证结果调整。Remotion 工程应与桌面应用共享明确的模板输入数据契约，由受控的本地渲染流程生成视频。

## 安全与发布边界

- 应用只向渲染进程暴露完成任务必需的接口；严格限制本地文件访问，参数在主进程再次校验。
- 云端 API 密钥使用 macOS 安全存储能力；不写入前端源码、日志、普通配置文件或导出项目。
- 素材、字幕和文案只有用户选择云端功能时才发送到相应服务，并说明数据去向和可能产生的费用。
- 打包 FFmpeg、模型、字体和模板前分别核对来源、许可证和再分发要求；Remotion 官方示例不等于可以无条件分发其中所有媒体。
- 正式发布前还需确认 macOS 签名、公证及第三方依赖许可。具体版本与实现以届时验证为准。
